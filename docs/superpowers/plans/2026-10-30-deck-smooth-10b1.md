# 10b-1: Programın kablo okuması — Uygulama planı

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Program kartın cevabını geldiği anda okusun (kapak, liste, küçük kapak onlarca kat hızlansın, uçak partileri atlanmasın); `perf.log` uçak/hava partilerini de yazsın. Kart değişmez.

**Architecture:** `device._read_loop` `ser.read(ser.in_waiting or 1)` ile okur. `send_batch` sonucu ve süresi `perf`'e yazılır. Test, pyserial'sız çalışan sahte bir seri port ile yerelde koşar.

**Tech Stack:** Python 3.12, pyserial; testte sahte `serial` modülü.

**Spec:** `docs/superpowers/specs/2026-10-30-deck-smooth-design.md` (10b-1)

## Global Constraints

- Yalnız program: `helper/deck/device.py`, `helper/app.py` `VERSION = "1.10.1"`. Kart yazılımı aynı (5in-0.42.0).
- `perf.log` satırı: `batch <etiket> <satır> ok|skipped|noanswer <sn> s` — etiket ilk satırın `PR:` etiketi (`ABEGIN` = uçak, `W` = hava); `skipped` = kablo meşgul (kilit alınamadı), `noanswer` = son satıra cevap yok.
- Kilit bekleme süresi `BATCH_WAIT = 5` (bugünkü değer) modül sabiti olur.
- Merge yalnızca "Birleştir" ile.

## Review Focus

- Okuma döngüsü boşta CPU yakmamalı: `in_waiting` 0 iken `read(1)` port zaman aşımı (0,2 sn) kadar bekler.
- Satır ortadan bölünerek gelirse (bir kısmı bir okumada, kalanı sonrakinde) satır yine tek parça işlenir (mevcut `buf` mantığı; test).
- Port kapanırken/`in_waiting` hata verirken döngü bugünkü gibi çıkar (`SerialException`/`OSError`).
- Mac (`media_mac` vb.) aynı `device.py`'yi kullanır: pyserial'ın `in_waiting`'i macOS'ta da var.
- Ayar sayfası (setup modu, USB-Serial/JTAG) yüklemeleri de aynı okumayı kullanır: harita/tuş/OTA aktarımı hızlanır, protokol aynı.
